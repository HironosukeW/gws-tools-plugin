# 初回セットアップの案内

このスキルは、ユーザーが `gws` を使える状態になるまでを案内する。**ブラウザでの承認はユーザー本人が行う。代行しない。** また、クライアントシークレットやトークンの中身を表示・複製・送信してはいけない。

やることは実質1つだけである。OAuth クライアントの情報はプラグインのインストール時に入力済みなので、**残っているのは自分の Google アカウントでの承認だけ**である。

## ステップ1: 現在地を確認する

```bash
gws auth status
```

出力の読み方は次のとおりである。

| 出力 | 意味 | 次にやること |
|---|---|---|
| `user` にメールアドレスが出て `token_valid: true` | 認証済み | ステップ3の動作確認へ |
| `credential_source` が `environment_variables` で `user` が出ない | クライアントは設定済み、未ログイン | ステップ2へ |
| `credential_source` が `none` / `No OAuth client configured` | プラグイン設定が未入力 | 下の「設定が入っていないとき」へ |

## ステップ2: 自分の Google アカウントで承認する

```bash
gws auth login
```

ブラウザが開くので、**会社の Google アカウント**（普段スプレッドシートを開いているアカウント）で承認する。個人の Gmail アカウントで承認すると、会社のスプレッドシートが見えない。

スコープの選択を求められたら、`spreadsheets` と `drive` を選ぶ。それ以外（Gmail・カレンダーなど）は不要なので選ばない。

## ステップ3: 動作確認

対象表シートが読めれば、セットアップは完了である。

```bash
gws sheets spreadsheets values get --params '{"spreadsheetId":"${user_config.registry_spreadsheet_id}","range":"対象表!A:D"}'
```

操作できるスプレッドシートの一覧が返ってくるので、それをユーザーに見せて「この中から選んで指示してください」と伝える。以降は `sheets-ops` スキルが担当する。

## 設定が入っていないとき

OAuth クライアントの情報（クライアント ID・クライアントシークレット・対象表のスプレッドシート ID）は、プラグインの設定画面で入力する。会社の管理者から渡された3つの値を用意して、`/plugin` を開き、`gws-sheets` の設定から入力してもらう。

値を持っていない場合は、管理者に問い合わせるよう案内する。**値をユーザーに推測させたり、こちらで代わりに用意しようとしたりしない。**

## つまずいたときの切り分け

| 症状 | 原因と対処 |
|---|---|
| `No OAuth client configured` | プラグイン設定が未入力。`/plugin` から3つの値を入れる |
| ブラウザで「このアプリは確認されていません」 | 会社の Workspace 内部アプリとして作られていない可能性がある。管理者に確認する |
| 承認したのに 403 が出る | ログインしたアカウントが違う。`gws auth status` の `user` を確認し、違えば `gws auth logout` してやり直す |
| 対象表が 404 | 対象表のスプレッドシート ID が誤っているか、自分に共有されていない。管理者に確認する |
| しばらく使っていたら認証が切れた | 通常は再ログインで直る。**数日おきに切れる場合**は OAuth クライアントが「テスト中」の外部アプリになっている疑いがあるため、管理者に「内部アプリになっているか」を確認してもらう |
